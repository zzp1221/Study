# 数据库设计文档

## 1. 数据库概述

### 1.1 数据库信息
- **数据库名称**: test
- **字符集**: utf8mb4
- **排序规则**: utf8mb4_unicode_ci
- **存储引擎**: InnoDB

### 1.2 系统简介
基于 Level 等级的动态权限管理系统，通过用户等级（level）和接口等级配置实现灵活的权限控制。

---

## 2. 数据表设计

### 2.1 用户表（user）

#### 表结构
| 字段名 | 数据类型 | 约束 | 默认值 | 说明 |
|--------|----------|------|--------|------|
| id | INT | PRIMARY KEY, AUTO_INCREMENT | - | 用户 ID |
| username | VARCHAR(50) | NOT NULL, UNIQUE | - | 用户名 |
| password | VARCHAR(100) | NOT NULL | - | 密码（加密后） |
| level | INT | - | 999 | 用户等级，数字越小权限越大 |
| deleteFlag | TINYINT | - | 0 | 删除标记：0-未删除，1-已删除 |
| create_time | DATETIME | - | CURRENT_TIMESTAMP | 创建时间 |
| update_time | DATETIME | - | CURRENT_TIMESTAMP ON UPDATE | 更新时间 |

#### 索引
| 索引名 | 字段 | 类型 | 说明 |
|--------|------|------|------|
| PRIMARY | id | 主键索引 | 唯一标识用户 |
| idx_username | username | 普通索引 | 加速用户名查询 |
| idx_level | level | 普通索引 | 加速用户等级查询 |

#### 字段说明
- **level**: 用户等级字段
  - level 1: 超级管理员
  - level 2: 管理员
  - level 3: 普通管理员
  - level 4-998: 自定义等级
  - level 999: 新用户（unknown）
- **password**: 加密格式为 salt(32 位) + MD5(password+salt)(32 位)

---

### 2.2 接口等级配置表（interface_level）

#### 表结构
| 字段名 | 数据类型 | 约束 | 默认值 | 说明 |
|--------|----------|------|--------|------|
| id | BIGINT | PRIMARY KEY, AUTO_INCREMENT | - | 配置 ID |
| interface_path | VARCHAR(200) | NOT NULL | - | 接口路径 |
| interface_method | VARCHAR(10) | NOT NULL | - | HTTP 方法 |
| allowed_levels | VARCHAR(500) | NOT NULL | - | 允许的等级列表（逗号分隔） |
| description | VARCHAR(500) | - | NULL | 描述信息 |
| status | TINYINT | - | 1 | 状态：1-启用，0-禁用 |
| create_time | DATETIME | - | CURRENT_TIMESTAMP | 创建时间 |
| update_time | DATETIME | - | CURRENT_TIMESTAMP ON UPDATE | 更新时间 |

#### 索引
| 索引名 | 字段 | 类型 | 说明 |
|--------|------|------|------|
| PRIMARY | id | 主键索引 | 唯一标识配置 |
| uk_path_method | (interface_path, interface_method) | 唯一索引 | 确保接口路径 + 方法唯一 |
| idx_allowed_levels | allowed_levels(100) | 普通索引 | 加速等级查询 |

#### 字段说明
- **interface_path**: 接口路径，支持通配符 `**`（如 `/api/user/**`）
- **interface_method**: HTTP 方法（GET, POST, PUT, DELETE 等）
- **allowed_levels**: 逗号分隔的等级列表
  - 示例：`"1"` - 只有 level 1 可访问
  - 示例：`"1,2"` - level 1 和 level 2 可访问
  - 示例：`"2,3,999"` - level 2、3、999 可访问
- **status**: 配置状态，0 表示禁用该权限配置

## 3. 权限规则

### 3.1 等级权限规则
1. **level 1（超级管理员）**: 可以访问所有接口，无需检查 allowed_levels
2. **其他用户（level 2+）**: 只能访问 allowed_levels 包含其等级的接口
3. **开放接口**: 登录、注册、CORS 预检请求不需要配置，任何人都可以访问
4. **未配置接口**: 没有配置的接口默认开放，所有人都可以访问

### 3.2 等级修改规则
- 高等级用户可以修改低等级用户的等级
- 不能修改等级 >= 自己的用户
- 不能将用户等级修改为 >= 自己的等级

示例：
- level 1 可以创建/修改 level 2, 3, 4, ..., 999
- level 2 可以创建/修改 level 3, 4, ..., 999

## 6. 安全说明

1. **密码加密**: 使用 salt + MD5 加密方式
   - 格式：salt(32 位) + MD5(password + salt)(32 位)
   - 实际使用时建议通过注册接口创建用户

2. **删除标记**: 使用 deleteFlag 字段实现逻辑删除，不物理删除数据

3. **权限验证**: 
   - 通过 LevelInterceptor 拦截器实现
   - 支持注解 @RequireLevel 和 @DynamicRequireAuthority
