# 全局异常处理说明

## 一、实现原理

通过 `@RestControllerAdvice` 注解创建全局异常处理器，拦截所有 Controller 和拦截器抛出的异常，并统一转换为 JSON 格式响应。

## 二、核心代码

### GlobalExceptionHandler.java

**文件位置：** [`GlobalExceptionHandler.java`](file://d:\项目\test\src\main\java\com\project\test\common\exception\GlobalExceptionHandler.java)

```java
@Slf4j
@RestControllerAdvice
public class GlobalExceptionHandler {

    // 处理 CommonException 异常
    @ExceptionHandler(CommonException.class)
    public Result handleCommonException(CommonException e) {
        log.error("业务异常：{}", e.getMessage());
        return Result.error(e.getMessage());
    }

    // 处理 IllegalArgumentException 异常
    @ExceptionHandler(IllegalArgumentException.class)
    public Result handleIllegalArgumentException(IllegalArgumentException e) {
        log.error("参数异常：{}", e.getMessage());
        return Result.error("参数错误：" + e.getMessage());
    }

    // 处理其他所有异常
    @ExceptionHandler(Exception.class)
    public Result handleException(Exception e) {
        log.error("系统异常：{}", e.getMessage(), e);
        return Result.error("系统错误：" + e.getMessage());
    }
}
```

## 三、响应格式

### 成功响应
```json
{
  "code": 200,
  "message": "操作成功",
  "data": {
    // 返回的数据
  }
}
```

### 错误响应
```json
{
  "code": 400,
  "message": "错误信息",
  "data": null

```

## 五、异常类型

### 1. CommonException（业务异常）

**触发场景：**
- 等级不足
- 用户不存在
- 密码错误
- 用户名已存在
- 等等...

**响应示例：**
```json
{
  "code": 403,
  "message": "等级不足，当前等级 999，需要等级 1",
  "data": null
}
```

### 2. IllegalArgumentException（参数异常）

**触发场景：**
- 参数格式错误
- 参数为空
- 参数超出范围

**响应示例：**
```json
{
  "code": 400,
  "message": "参数错误：用户名不能为空",
  "data": null
}
```

### 3. Exception（系统异常）

**触发场景：**
- 数据库连接失败
- 空指针异常
- 其他未预期的异常

**响应示例：**
```json
{
  "code": 500,
  "message": "系统错误：NullPointerException",
  "data": null
}
```

## 八、优势

### 1. 统一响应格式
所有错误都返回统一的 JSON 格式，前端易于处理

### 2. 隐藏实现细节
不暴露堆栈信息，提高安全性

### 3. 便于日志记录
自动记录所有异常日志，便于排查问题

### 4. 代码简洁
不需要在每个 Controller 中手动 try-catch

## 十、注意事项

1. **生产环境**：建议关闭详细错误信息，只返回通用错误消息
2. **日志级别**：生产环境建议使用 INFO 或 WARN 级别
3. **异常分类**：可以根据需要添加更多特定类型的异常处理
4. **响应码**：可以根据实际情况调整 HTTP 响应码
